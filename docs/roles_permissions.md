# Ролевая модель доступа и права пользователей (RBAC)

---

## 1. Сводная таблица прав доступа
В системе Suluu Business реализовано 4 уровня доступа: Суперадминистратор, Владелец, Менеджер и Мастер. Каждый уровень имеет свои ограничения в интерфейсе и на сервере (RLS).

| Действие / Раздел | Super Admin | Owner (Владелец) | Manager (Менеджер) | Master (Мастер) |
|:---|:---:|:---:|:---:|:---:|
| **Администрирование всей базы данных** | ✅ Да | ❌ Нет | ❌ Нет | ❌ Нет |
| **Управление глобальными шаблонами** | ✅ Да | ❌ Нет | ❌ Нет | ❌ Нет |
| **Регистрация салона и базовые настройки** | ✅ Да | ✅ Да | ❌ Нет | ❌ Нет |
| **Включение / отключение учета финансов** | ✅ Да | ✅ Да | ❌ Нет | ❌ Нет |
| **Прием менеджеров/мастеров на работу** | ✅ Да | ✅ Да | ❌ Нет | ❌ Нет |
| **Удаление кошельков и касс** | ✅ Да | ✅ Да | ❌ Нет | ❌ Нет |
| **Полный просмотр финансового баланса** | ✅ Да | ✅ Да | ✅ Да (опция) | ❌ Нет |

## 2. Спецификация ролей

### 2.1. Владелец салона (`owner`)
- **Статус**: Создатель организации.
- **Возможности**:
  - Регистрирует компанию и привязывает к своему ID в `public.business`.
  - Управляет настройками салона: адрес, логотип, контакты, рабочий график, тема оформления, валюта.
  - Принимает заявки от сотрудников в разделе «Сотрудники» (переводит статус `business_members` в `approved`).
  - Управляет правами доступа менеджеров, выдавая индивидуальные разрешения (`permissions` JSONB).
  - Активирует/деактивирует тумблер `use_finance` (учет финансов) в профиле салона.
  - Обладает полной видимостью по всем транзакциям, сменам и кошелькам без ограничений.

### 2.2. Менеджер салона (`manager`)
- **Статус**: Наемный администратор. Подает заявку на вступление в салон владельца.
- **Возможности**:
  - Управляет текущей деятельностью: расписание, создание и ведение визитов, регистрация клиентов.
  - Контролирует смены мастеров, регистрирует транзакции в соответствии с выданными правами.
  - Настройка прав для менеджера хранится в объекте `permissions` в таблице `business_members`. Владелец может индивидуально отключить менеджеру:
    - Просмотр финансовых отчетов.
    - Изменение каталога услуг.
    - Удаление записей.
    - Редактирование карточек персонала.

### 2.3. Мастер (`master`)
- **Статус**: Исполнитель услуг (сотрудник). Подает заявку на вступление в салон владельца.
- **Возможности**:
  - Доступ к приложению ограничен его собственным профилем и личным календарем.
  - Не видит расписания других мастеров салона (если это не разрешено глобально).
  - Имеет доступ только к чтению списка оказываемых им услуг.
  - Видит статистику собственной выработки и сумму начисленной заработной платы за смену/период на основе его персонального процента (при включенном модуле финансов).

### 2.4. Суперадминистратор (`super_admin`)
- **Статус**: Глобальный управляющий платформы (логин `admin`).
- **Возможности**:
  - Обладает абсолютными правами на чтение и запись любых таблиц в БД, минуя стандартные ограничения по `business_id` (через специальную RLS политику проверки функции `is_super_admin`).
  - Управляет глобальной базой категорий и шаблонов услуг, обеспечивая их корректный импорт новыми салонами.
  - Осуществляет мониторинг активности системы.

## 3. Проверка прав на клиенте
На стороне клиента разграничение доступа реализуется через функцию `window.hasPermission(permissionName)` в [router.js](file:///d:/%D0%A0%D0%B0%D0%B1%D0%BE%D1%87%D0%B8%D0%B9%20%D1%81%D1%82%D0%BE%D0%BB/Code%20Projects/BeautyPlace/business/js/core/router.js):

```javascript
window.hasPermission = function(permissionName) {
  const role = state.userProfile?.role || 'master';
  if (role === 'owner' || role === 'super_admin') return true;
  if (role === 'master') {
    // Жестко закодированные права для мастеров
    if (permissionName === 'dashboard_view') return true;
    if (permissionName === 'bookings_view') return true;
    if (permissionName === 'settings_view_profile') return true;
    return false;
  }
  if (role === 'manager') {
    // Проверка кастомных разрешений менеджера
    const activeEmployment = (state.myEmployments || []).find(
      e => e.business_id === state.ui.activeBusinessId && e.status === 'approved'
    );
    const permissions = activeEmployment?.permissions || {};
    return permissions[permissionName] !== false; // По умолчанию true, если не запрещено владельцем
  }
  return false;
};
```
Эта функция блокирует переходы по вкладкам в `window.navigate(page)` и скрывает запрещенные элементы интерфейса (кнопки удаления, добавления, финансовые карточки) на этапе генерации HTML-разметки страниц.
