# Техническое задание (ТЗ) и Спецификация проекта: Suluu Business

---

## 1. Назначение системы
**Suluu Business** — это автономная экосистема и CRM-платформа, разработанная для автоматизации операционных процессов в салонах красоты, бьюти-коворкингах и у частных мастеров. Система обеспечивает планирование расписания, управление клиентской базой, учет рабочего времени и смен сотрудников, расчет сдельной оплаты труда, а также финансовый учет доходов и расходов в мультитенантной среде.

---

## 2. Технологический стек
Для обеспечения максимальной производительности, легкой переносимости и работы в режиме Offline-First выбран следующий стек технологий:

### 2.1. Frontend (Клиентская часть)
- **Ядро**: HTML5, CSS3, ES6+ JavaScript (без использования тяжеловесных фреймворков для минимизации оверхеда).
- **Стилизация**: Tailwind CSS (встроенный локальный билд `js/tailwind.min.js` для оффлайн-совместимости).
- **Патчинг DOM (SPA)**: [morphdom](https://github.com/patrick-steele-idem/morphdom) для сверхбыстрого и реактивного обновления DOM-дерева без полной перезагрузки страниц.
- **Иконки**: Feather Icons (рендеринг в SVG на клиенте).
- **Поддержка PWA**: Service Worker (`sw.js`) для кэширования статических ресурсов и манифест приложения (`manifest.json`) для возможности нативной установки на мобильные устройства и десктопы.

### 2.2. Backend & Database (Серверная часть)
- **Платформа**: **Supabase** (Бэкенд-как-сервис на базе PostgreSQL).
- **СУБД**: PostgreSQL 15 с расширениями `uuid-ossp` и `pgcrypto`.
- **Авторизация**: Supabase Auth (регистрация по email/логину, генерация сессионных токенов JWT).
- **Realtime**: Supabase Realtime (автоматическая синхронизация изменений данных во всех открытых вкладках клиентов через веб-сокеты).
- **Безопасность**: Row Level Security (RLS) политики на уровне СУБД для разграничения доступа к записям между салонами и ролями.

## 3. Функциональные модули
Система состоит из следующих взаимосвязанных функциональных модулей:

### 3.1. Интерактивный лендинг (Стартовый экран)
- Отображается только для неавторизованных пользователей.
- Содержит описание возможностей, детальную интерактивную панель-симулятор приложения для ролей Владельца, Менеджера и Мастера.
- Предоставляет форму обратной связи с прямой переадресацией сообщений на WhatsApp администратора (`+99650888268`).

### 3.2. Авторизация и Управление Тентами (Салонами)
- Регистрация пользователя с выбором роли (`owner` / `manager` / `master`).
- Для владельцев — автоматическое создание организации (салона) с дефолтными настройками и возможностью включить/отключить учет финансов.
- Для менеджеров и мастеров — система подачи заявок (`business_members`) на вступление в существующие салоны с последующим подтверждением владельцем.
- Возможность переключения между несколькими доступными салонами в рамках одной учетной записи.

### 3.3. Интерактивный календарь (Записи)
- Отображение сетки расписания (таймлайн с часовым шагом) в разрезе мастеров.
- Быстрое создание записей в один клик.
- Поддержка мульти-услуг для одной записи (хранение массива выбранных услуг в формате JSONB).
- Управление статусами записи: `pending` (Ожидается), `in_progress` (В процессе), `completed` (Выполнено), `cancelled` (Отменено).

### 3.4. Управление персоналом (Мастера)
- Ведение картотек мастеров: имя, специализация, рабочий телефон, аватар, процентная ставка за выполнение услуг.
- Учет рабочих смен и расписания мастеров.
- Автоматический расчет начисленной заработной платы мастера на основе выполненных им записей.

### 3.5. База клиентов
- Картотека клиентов с контактными данными.
- Автоматический сбор аналитики: количество совершенных визитов, суммарный оборот (принесенная выручка), дата последнего посещения.

### 3.6. Каталог услуг и Шаблоны
- Классификация услуг по категориям.
- Интеграция с глобальным каталогом шаблонов (50+ готовых услуг).
- Возможность пакетного импорта и редактирования шаблонов услуг на одной странице с кнопкой сохранения в шапке.

### 3.7. Учет финансов (Опциональный блок)
- Создание кошельков и касс салона (наличные, терминал, счета).
- Классификация транзакций доходов и расходов.
- Отчетность по кассовым сменам сотрудников (открытие смены, внесение остатка, закрытие, инкассация).
- Полная деактивация финансового контура: при отключении опции `use_finance` в профиле салона, все разделы транзакций, смен и кошельков скрываются из интерфейса, а на дашборде отображается только статистика визитов и средний чек.

### 3.8. Панель Суперадминистратора
- Доступна пользователям с ролью `super_admin` (логин: `admin`).
- Позволяет управлять глобальными справочниками (шаблоны услуг, глобальные категории).
- Предоставляет аудит всех зарегистрированных салонов и профилей пользователей в системе.

## 4. Системные требования и Ограничения
- **Адаптивность**: Интерфейс должен полностью масштабироваться под экраны смартфонов (от 320px до 480px), планшетов и десктопов.
- **Оффлайн-режим**: Статические файлы кэшируются Service Worker. В случае обрыва сети PWA должно продолжать открываться и отображать ранее закэшированные данные.
- **Производительность**: Время отклика интерфейса на переключение вкладок не должно превышать 100мс благодаря патчингу через morphdom.
